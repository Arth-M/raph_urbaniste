0. PÉRIMÈTRE ET MÉTHODE
==================================================================
- Type : site vitrine Next.js 16 (App Router), React 19, Tailwind v4, en français uniquement. Cabinet d'urbanisme (Raphaël Sinet / Novurba, Occitanie). Public visé : collectivités (métropoles, mairies, communes).
- Pages auditées (code source) : / (app/page.jsx), /notre-expertise, /nos-realisations, /entreprise, /contact, /sitemap. Composants : navbar, footer, carousel, arrowUp, layout.js, globals.css.
- Niveau de référence : WCAG 2.1 AA. Le site n'appartient pas au secteur public, donc le RGAA n'est pas obligatoire. Comme les clients sont des collectivités, le RGAA reste un argument commercial.
- Limite de l'audit : revue statique du code uniquement. Je n'ai pas lancé de serveur ni de navigateur (mode readonly, pas d'install ni de build). Donc pas d'axe, Lighthouse, Pa11y, WAVE, pas de lecteur d'écran et pas de test sur appareil réel. Les contrastes ont été calculés à partir des tokens de globals.css (formule WCAG, script python local). Les points qui ne se vérifient qu'au rendu sont marqués « non vérifié ».
- État du site : tout le site est derrière une porte « code d'accès » côté client (layout.js, code '34000' en dur, sessionStorage). C'est donc encore une pré-production. Les métadonnées et le JSON-LD sont commentés avec la note « REMETTRE LES METADATA QUAND ON MET LE SITE EN LIGNE ».

==================================================================
1. SYNTHÈSE EXÉCUTIVE
==================================================================
Maturité frontend/a11y : 2/5. Conformité WCAG 2.1 AA estimée : NON ATTEINTE.

Points positifs : `lang="fr"` présent sur `<html>`. Une partie des SVG décoratifs ont `aria-hidden`. Le bouton « Retour en haut » a un `aria-label`. Les couleurs sont centralisées en tokens `@theme`. Le site est responsive (breakpoints Tailwind sm/md/lg utilisés partout). Les polices sont chargées avec `display: swap`.

Top 5 des problèmes bloquants :
 1. Carrousel en défilement auto (2,5 s) sans pause ni arrêt. Boutons flèche sans nom accessible. Lien vide superposé à l'image. [2.2.2 A, 4.1.2 A, 2.4.4 A]
 2. Contrastes de texte insuffisants sur les couleurs de marque, partout sur le site. [1.4.3 AA, 1.4.11 AA]
 3. Liens icônes sans nom accessible : tel et mail sur /entreprise. Le menu hamburger a un libellé en anglais et pas d'`aria-expanded`. [4.1.2 A, 2.4.4 A, 3.1.2 AA]
 4. Pas de `<title>`, pas de `<main>`, plusieurs h1 ou aucun h1 selon la page, pas de skip link. [2.4.2 A, 1.3.1 A, 2.4.1 A]
 5. `prefers-reduced-motion` n'est jamais respecté (slide du h1, ping, drop-in, scale au scroll, défilement auto). Débordement horizontal probable (faute de frappe `overflow-hiddenw-fit`, `w-screen`, `min-w-[360px]`). [2.3.3 AAA / bonne pratique, 1.4.10 AA]

--- §1 Responsive design ---
[MAJEUR] Débordement horizontal sur la home pendant l'animation du h1.
  app/page.jsx:63 : `className="relative w-full overflow-hiddenw-fit ..."`. La faute de frappe (espace manquant) fait que la classe `overflow-hidden` n'est jamais appliquée. Le h1 démarre en `translate-x-full` (l. 80) et glisse pendant 2500 ms : il dépasse du viewport à droite. Un `<div>` blanc absolu (l. 64, `hidden sm:block`) sert de cache-misère. Correctif : `overflow-hidden w-fit`. [1.4.10 AA]
[MAJEUR] `w-screen` sur nav et footer (navbar.jsx:31-34, footer.jsx:10). 100vw inclut la largeur de la barre de défilement sur desktop (Windows, Firefox, Chrome) et provoque un scroll horizontal. Remplacer par `w-full`. (Non vérifié au rendu, mais c'est un comportement CSS connu.)
[MAJEUR] /nos-realisations : `min-w-[360px] px-8` sur les blocs texte (l. 96, 151, 180). Le contenu ne reflow pas à 320 px ou en zoom 400 %. [1.4.10 AA]
[MINEUR] Home : nom et fonction du dirigeant en positionnement absolu avec offsets négatifs (`-right-22`, `-right-31`, app/page.jsx:120-125). Risque de débordement ou de chevauchement aux largeurs intermédiaires. Footer : marges négatives (`sm:-mt-19`, `-mt-20`) fragiles.
[MINEUR] Cibles tactiles : boutons du carrousel 30×30 px (carousel.jsx:41, 55), sous les 44 px recommandés. ArrowUp : environ 39 px (p-3 + icône 15 px).
[MINEUR] Safe areas iOS non gérées (`env(safe-area-inset-*)` absent) pour le bouton fixe ArrowUp.
[OK] Le corps de texte est en text-lg ou text-xl (≥18 px). Images en w-% / object-*.

3. QUICK WINS (fort impact, faible effort)
==================================================================
1. app/page.jsx:63 : `overflow-hiddenw-fit` → `overflow-hidden w-fit`.
2. carousel.jsx : `aria-label="Diapositive précédente"` / `"Diapositive suivante"`. Supprimer le `<a>` vide superposé ou lui donner un texte (« Voir : {text} »). Mettre l'auto-défilement en pause au survol, au focus et avec un bouton Pause, ou le désactiver.
3. navbar.jsx : `aria-expanded={isMobileMenuOpen}`, `aria-controls`, sr-only « Ouvrir le menu », Escape pour fermer, `aria-current="page"` sur le lien actif.
4. entreprise/page.jsx : `aria-label="Appeler Novurba"` / `"Écrire à Novurba"` sur les liens icônes (ou `aria-hidden` + `tabIndex={-1}` puisqu'ils doublent les liens texte). Retirer la copie LinkedIn focusable. « LinkedIn profile » → « Page LinkedIn de Novurba ».
5. Alt des logos clients : mettre les vrais noms.
6. layout.js : envelopper `{children}` dans `<main id="contenu">`, ajouter un skip link, puis à la mise en ligne retirer 'use client' du layout et rétablir `metadata` avec un `title` par page (`export const metadata` ou `generateMetadata` dans chaque page, qui doit alors être un composant serveur).
7. Remplacer `w-screen` par `w-full` dans le nav et le footer.
8. Ajouter `motion-reduce:animate-none motion-reduce:transition-none` sur les éléments animés, ou un bloc `@media (prefers-reduced-motion: reduce)` global.
