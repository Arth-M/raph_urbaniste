# Synthèse audit plateforme — raph_sinet_urbaniste (site vitrine Novurba)
Date : 2026-10-06 · Périmètre : security, perf, seo, frontend, dependances, quality, resilience · Méthode : 7 sous-agents readonly (audit-platform)

## Synthèse exécutive globale
Le site est un site vitrine Next.js 16 / React 19 / Tailwind 4 entièrement statique : pas de backend, pas d'API, pas de base de données, pas de formulaire. La surface d'attaque est minimale, mais le site est en pré-production et n'est pas prêt pour la mise en ligne.

Le problème qui revient dans les 7 audits est le root layout `app/layout.js`. Il est en `'use client'` et cache le site derrière un code d'accès vérifié côté client (« 34000 », en clair dans le bundle JS et contourné via sessionStorage). Conséquences :
- aucune protection réelle (sécurité) ;
- contenu absent du HTML rendu côté serveur, donc rien d'indexable et des metadata impossibles (SEO) ;
- LCP qui dépend de l'hydratation (perf) ;
- pas de `<title>` ni de `<main>` (a11y) ;
- page blanche si le JS échoue (résilience).

Les autres thèmes transverses :
- Images sources de 2,5 à 4,4 Mo et environ 20 `preload` abusifs.
- Next 16.3.3 touché par une CVE critique (non atteignable aujourd'hui) et typed.js 3.0.0 passé sous GPL-3.0, alors que l'import est mort.
- Domaine novurba.fr pas encore raccordé : pas de HTTPS, page parking OVH.
- Incohérence de données : deux numéros de téléphone différents entre /contact et /entreprise.
- Aucun outillage qualité (lint, format, CI) ni aucune documentation de reprise.

Maturité moyenne : 1,7/5.

## Quick wins transverses (top 10)
1. Mettre à jour Next.js et les dépendances : `npm audit fix` (next ≥16.3.6, postcss, baseline-browser-mapping), puis `npm run build`.
2. Supprimer l'import mort de typed.js et la dépendance (ce qui règle aussi le risque GPL).
3. Corriger la faute de frappe `overflow-hiddenw-fit` en `overflow-hidden w-fit` (app/page.jsx:63), qui cause un débordement horizontal.
4. Retirer `preload` partout sauf sur l'image LCP de chaque page et ajouter `sizes` sur les images responsives.
5. Recompresser fond2.png, strat_fonciere.png, sig.png, strat-fonc-realisations.png et village_photo.jpg.
6. Ajouter app/error.jsx, global-error.jsx et not-found.jsx en français.
7. Ajouter les aria-label en français (carrousel, hamburger avec aria-expanded, icônes tel et mail) et supprimer le lien vide du carrousel.
8. Unifier le numéro de téléphone (à valider avec le client) et mettre les vrais noms dans les alt des logos clients.
9. Installer ESLint (eslint-config-next) et Prettier en devDependency avec `.editorconfig`, puis purger le code mort et le code commenté.
10. Écrire une fiche de reprise d'une page (hébergeur, comptes, DNS, build, rollback) et ajouter `.nvmrc` (Node 22 ou 24 LTS) et `.github/dependabot.yml`.

## Détail par domaine (AUDIT_RESUME)

### security
- Maturité : 2/5. Statut : partial (déploiement réel et TLS de l'application non vérifiables).
- Risques :
  - Code « 34000 » vérifié côté client, en clair dans le bundle et contournable par sessionStorage.
  - next 16.3.3 touché par GHSA-vcvr-r3jv-pc5j (non exploitable sans next/og), plus source-map-js et baseline-browser-mapping.
  - Aucun en-tête de sécurité, X-Powered-By actif, pas de HTTPS sur novurba.fr.
- Quick wins :
  - `npm audit fix`.
  - Protection côté serveur (Vercel Deployment Protection ou Basic Auth) ou suppression du gate.
  - next.config.mjs avec headers() et poweredByHeader:false, HTTPS avec 301, DMARC.

### perf
- Maturité : 2/5. Statut : partial (aucune mesure Lighthouse ou terrain, pas de build de production).
- Risques :
  - Layout client avec gate : contenu absent du SSR, LCP qui dépend de l'hydratation.
  - Images énormes : fond2.png 3,7 Mo en fond CSS, village_photo.jpg 4896 px, strat_fonciere.png 4,4 Mo.
  - Environ 20 `preload` dont des doublons masqués ; aucun `sizes`.
- Quick wins :
  - Recompresser et redimensionner les images, fond via `<Image fill>`.
  - Un seul preload par page, ajout de `sizes`, suppression des doublons.
  - Layout en Server Component.

### seo
- Maturité : 1/5. Statut : partial (pas de Search Console, pas de mesure CWV, HTTPS testé depuis un seul réseau).
- Risques :
  - HTML serveur limité au formulaire de gate, sans title ni description : rien d'indexable.
  - Domaine non raccordé (parking OVH en noindex, pas de HTTPS, 302 vers http://www) et en désaccord avec sitemap et robots.
  - Canonical prévu global vers l'accueil, pages client incapables d'exporter metadata, NAP incohérent, pas de mentions légales.
- Quick wins :
  - Metadata serveur par page avec canonical auto-référent.
  - Téléphone unifié, un H1 par page.
  - Host canonique avec 301, JSON-LD corrigé et réactivé.

### frontend
- Maturité : 2/5. Statut : partial (revue statique, sans navigateur ni outil a11y).
- Risques :
  - Carrousel auto sans pause, boutons sans nom accessible, lien vide superposé.
  - Contrastes de marque insuffisants (2,86:1, 2,93:1, 1,86:1).
  - Pas de `<main>` ni de `<title>`, 3 H1 sur /nos-realisations et aucun sur /notre-expertise, liens icônes tel et mail sans nom.
- Quick wins :
  - aria-label en français, aria-expanded sur le hamburger, suppression du lien vide et du doublon LinkedIn.
  - Pause du carrousel et `motion-reduce`.
  - Couleurs texte plus foncées, correction de `overflow-hiddenw-fit`, ajout de `<main>` et `<title>`.

### dependances
- Maturité : 2/5. Statut : success.
- Risques :
  - typed.js 3.0.0 sous GPL-3.0 dans un projet MIT commercial.
  - next 16.3.3 avec CVE critique (non atteignable).
  - source-map-js et baseline-browser-mapping (build uniquement) ; pas de dependabot.yml ; Node non fixé (Node 20 local EOL).
- Quick wins :
  - Rafraîchir le lock (next 16.3.8, postcss 8.5.29, baseline-browser-mapping ≥2.11).
  - Remplacer ou supprimer typed.js.
  - `.github/dependabot.yml`, `.nvmrc`, `packageManager`, prettier en devDependency.

### quality
- Maturité : 1/5. Statut : success.
- Risques :
  - Aucun outillage (lint, format, EditorConfig, hooks, CI), style incohérent.
  - Layout client avec gate en dur et environ 80 lignes de metadata et JSON-LD commentées : dette bloquante pour la mise en production.
  - Duplication forte, qui a déjà produit une divergence (deux numéros de téléphone).
- Quick wins :
  - ESLint et Prettier avec `.editorconfig` et les scripts lint et format:check.
  - Purge du code mort (Script, Typed, useRef, visibleCard*, activeCard, JSX commenté).
  - Constantes CONTACT et NAV_LINKS partagées.

### resilience
- Maturité : 2/5. Statut : success.
- Risques :
  - Aucune error boundary et un layout client : page blanche en cas d'exception.
  - Pas de procédure de redéploiement ou de rollback, pas de RTO/RPO, hébergeur non documenté.
  - SPOF non formalisés (compte GitHub, hébergeur, domaine et DNS, rendu 100 % JS).
- Quick wins :
  - error.jsx, global-error.jsx et not-found.jsx, et gardes null dans page.jsx.
  - Fiche de reprise d'une page, gardée hors du repo.
  - Miroir du repo et test de reconstruction depuis un clone propre.
